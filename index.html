Evidence Boundary

Blockchain records provide on-chain transaction facts. Any IP or identity information must come from separate authorized off-chain intelligence and should be stored with source, timestamp and confidence metadata.

Methodology

Research-grounded architecture and limitations.

Research basis

ChainSight is inspired by Pocher et al. (2023), which investigates anomalous cryptocurrency transactions for AML/CFT using machine-learning and graph-based approaches, including GCN and GAT.

Prototype pipeline

Transaction data → feature extraction → directed graph → explainable pattern detection → risk score → investigator visualization/report.

Planned ML extension

The current demo uses deterministic, explainable rules. A production/research version can train Random Forest/XGBoost baselines and then implement GCN/GAT using a labeled cryptocurrency transaction dataset.

IP intelligence limitation

A transaction hash does not inherently expose the originator's IP address. ChainSight therefore treats IP/identity information as an optional off-chain intelligence layer requiring lawful access or authorized datasets.

Responsible-use boundary

The risk score is an investigative prioritization signal, not proof of criminal conduct. Analysts should validate alerts against primary evidence and document provenance.
